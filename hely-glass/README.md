# hely 玻璃显标片：Apple Music 新视觉发布片复刻

**在线学习页：** https://opc8838-hub.github.io/movie/hely-glass/ （可交互的变速曲线、玻璃生命周期、逐镜关键帧）

复刻 Apple Music 新品牌视觉的发布短片。苹果的结构、节奏和玻璃动效一比一还原，内容全部换成我们的：

- 开头和结尾：苹果 logo + music 换成 **h 圆标 + hely.fun** 整组字标
- 中间四个镜头里的玻璃音符换成 **h 图标**
- 镜头画面：① 篝火面具舞（我的素材）② 湖边长椅、风吹头发（我的 Live 图）③ 白天滑板 ④ 黄昏花店、车经过（③④ 用 MiniMax 生成）

成片 1920×1080，30fps，12 秒，共 360 帧。定稿是 **v12**，迭代了 12 版。

---

## 观点：值得学的不是那块玻璃

Apple Music 新视觉出来以后，全球设计师都在复刻那块 **Liquid Glass（液态玻璃）**：厚边折射、边缘彩虹色散、像水一样出现和消失。

我更看重的是它发布片的 **动态语法（Motion Language）**：logo 怎么出场，节奏怎么走，图形和画面怎么配合。玻璃效果很快会被用烂，这套语法却可以沉淀成自己的视觉体系，直接用到之后的 TVC 和品牌广告里。

拆完参考片，我把这套语法归纳成下面 **六条规则**。

---

## 方法论：六条规则

### 1. 节拍网格（Beat Grid）：剪辑点由音乐决定

参考片是 80 BPM。每个镜头 2 拍，也就是 1.5 秒，到点就硬切（Hard Cut）。

| 段落 | 时间 | 帧号 |
|---|---|---|
| 开头字标 | 0 – 1.133 s | 0 – 33 |
| 镜头 ① 篝火 | 1.133 – 2.633 s | 34 – 78 |
| 镜头 ② 湖边 | 2.633 – 4.133 s | 79 – 123 |
| 镜头 ③ 滑板 | 4.133 – 5.633 s | 124 – 168 |
| 镜头 ④ 花店 | 5.633 – 7.133 s | 169 – 213 |
| 黑场玻璃 → 结尾字标 | 7.133 – 12.0 s | 214 – 359 |

切点是用 ffmpeg 的 `scene>0.25` 测出来的，再按录屏每帧的真实时间戳（PTS）逐帧核对，误差不到半帧。

### 2. 玻璃生命周期：每个镜头都走同一条时间线

镜头内的时间记作 **r**（秒），每个镜头都从 0 走到 1.5：

| r | 发生什么 |
|---|---|
| 0 – 0.15 | 只有画面，没有玻璃 |
| **0.15** | 水滴落下，logo 震动（**冲击帧**） |
| 0.15 – 0.30 | 水滴长成圆角方砖，折射和色散出现 |
| 0.30 – 0.95 | 方砖停在画面正中，左右两侧荡出冲击波 |
| **0.95** | 玻璃开始退场 |
| 0.95 – 1.22 | 玻璃消失，留下干净的白色 h |
| **1.5** | 硬切下一个镜头 |

logo 始终 **固定在画面正中，不漂移，不跟人走**。这条我们试过反面：v3 让玻璃跟着滑板手移动，被否了。

### 3. 变速（Speed Ramp / Time Remapping）：冲击帧放慢，退场后加速

这是整片最关键的一条。我们用光流测了参考片每一镜的运动量，发现画面速度跟着玻璃的节点走：

```
正常速度 ──► 冲击帧 r≈0.15 骤然放慢 ──► 玻璃在的整段都是慢动作 ──► r≈0.95 玻璃退场后加速 ──► 冲进硬切
```

我们的定稿数值：

| 镜头 | 进场 | 慢动作（含水滴和玻璃段） | 加速冲刺 |
|---|---|---|---|
| ① 篝火 | 1.2× | 0.30×，r 0.20 – 0.90 | 2.0×，r 1.05 起，叠 3 子帧运动模糊 |
| ② 湖边 | 1.0× | 0.40×，r 0.25 – 1.00 | 回到 1.0× |
| ③ 滑板 / ④ 花店 | 1.0× | 0.45×，r 0.28 – 0.95 | 1.6×，r 1.12 起 |

速度之间都用 smoothstep 平滑过渡，不跳变。

**慢动作必须插帧。**直接放慢会一卡一卡（v1 篝火就因此被说"卡顿"）。用 ffmpeg 运动补偿插帧到 120fps 再取样：

```
minterpolate=fps=120:mi_mode=mci:mc_mode=aobmc:me_mode=bidir:vsbmc=1
```

插完放大到 200% 看火焰、刀、发丝边缘有没有撕裂。

### 4. 动作对位（Action Sync）：画面动作卡在玻璃节点上

参考片里，素材自己的动作起点都落在冲击帧 r≈0.15，第二个动作落在 r≈0.75 左右，玻璃退场 r≈1.0 时主体到达最佳位置。logo 不是贴在画面上的，看起来像是被画面里的动作"撞"出来的。

做法：入点不靠感觉选，而是用 OpenCV Farneback 光流算出素材每一帧的运动量，在整条素材里滑动一个 1.5 秒的窗口打分，挑动作起点刚好落在 r=0.15 和 0.75 的那一段（脚本 `scripts/tools/fire_candidates.py`）。

- ① 篝火：r=0.15 刀举起，r=0.75 锣举起，r=1.0 面具正对镜头
- ② 湖边：头发最大在 r≈0.375，同时 1.00 → 1.28 猛推近（expo 缓动）
- ③ 滑板：起跳在 r≈0.15，最高点 r=0.30（生成时要求跳得早）
- ④ 花店：车在 r≈0.8 进画，横向带动态模糊开过。不擦黑，第 214 帧直接硬切纯黑

### 5. 推拉（Dolly In / Out）：数码推拉强化节奏

只有篝火镜头加了推拉，围绕面具附近 (960, 480) 缩放：

| r | 缩放 | 感觉 |
|---|---|---|
| 0 – 0.15 | 1.00 → 1.10，easeOutCubic | 切进来就往里冲 |
| 0.15 – 0.90 | 1.10 → 1.02，smoothstep | 慢动作里"呼一口气"，慢慢拉远 |
| 0.90 – 1.50 | 1.02 → 1.20，easeInCubic | 加速猛推，冲进硬切 |

推拉要用原片完整画面去做，**不准为了推拉先把画面放大裁掉**。v2 的篝火做了 1.25 倍 overscan、右扫和去块（deblock），结果面具和人都被裁出画面，画面也糊了，用户一眼看出来。

### 6. 冲击波（Shockwave）与流体字标（Fluid Wordmark）

**镜头里：方砖两侧的冲击波。**方砖成形后，左右两侧各发出一道波，从方砖边往外走，先快后慢、由深变浅，大约 0.5 秒走出 0.36 个方砖宽后消失。隔一会儿再发一道更淡的。每道波是一片薄玻璃：两条挨得很近的亮弧，中间把背景折射错位。上下两边几乎没有波。

| 参数 | 值 |
|---|---|
| 发波时刻 | r = 0.50（强度 1.0）、r = 0.70（强度 0.55） |
| 走多远 / 走多久 | 0.36 个方砖宽 / 0.5 秒 |
| 运动缓动 | `1 - (1-p)^2.4`，出边快、越走越慢 |
| 淡出 | `(1-p)^1.6`，由深到浅 |
| 两条弧间距 | 0.022 个方砖宽 |
| 折射错位 | 20 px |

**开头和结尾：字标的流体展开。**透镜先在中间打旋（字始终水平，只有透镜里的内容在转），然后从中间向左右撑开，两端按 R、G、B 三个通道分别拉长，形成红蓝分离的色散（Chromatic Aberration），最后收拢定格。左右各有一道括号形 "( )" 震动波往外推。0.6 秒后字标完整可读，背景是干净的纯色。

## 详细做法：从素材到成片

```
素材准备 → 拆参考 → logo 矢量化 → 镜头背景（变速/推拉/质感）→ 玻璃渲染（WebGL）→ 后处理（冲击波/字标）→ 声音 → 合成编码 → 验收
```

### 第 0 步　准备素材

- 两段实拍：篝火 1088×720 30fps；Live 原视频 1280×720 HEVC
- 两段生成：MiniMax 海螺视频，图生视频。提示词要求真实、动作卡在前 0.3 秒（滑板起跳要早）
- 生成镜头统一做一层 **很轻的质感**，不改色：

  | 处理 | 数值 |
  |---|---|
  | 轻微柔化 | gblur 0.4 |
  | 抬黑位 | 7/255 |
  | 高光柔压 | ≤ 248 |
  | 细颗粒 | σ≈2.2/255 |
  | 亮部光晕 | 4% |
  | 暗角 | 无 |
  | 色相 | 不动 |

### 第 1 步　拆参考：把"感觉"变成数字

参考片是手机录屏，16:9 画面在 `crop=592:334:0:335`，可变帧率。拆的时候用这些方法：

| 方法 | 用来看什么 |
|---|---|
| 解出全部实际帧和 PTS | 不把录屏当恒定帧率，每帧时间都是真的 |
| `scene>0.25` 测切点 | 切点时间 |
| 逐帧量方砖宽度、中心 | 玻璃大小（画宽 26–28%）、字标宽度（画宽 42%） |
| **高通增强**：灰度减去高斯模糊 ×8~14 | 看清肉眼看不见的淡波纹、柔光泡、灰边 |
| **mpdecimate 去重帧后平铺** | 一张图看完一道波怎么走 |
| **光流运动曲线** | 每镜哪里放慢、哪里加速 |

**教训：**冲击波这一项改了 5 版（v8 到 v12），每次都是"看懂了一半"。直到逐帧去重平铺、高通放大，才看清它是"一次一道、往外走、由深到浅"，不是几条静止的线。看不清的时候，先换方法看，不要急着改参数。

### 第 2 步　logo 矢量化：一定要干净通透

原图是带噪点的 JPEG，不能直接抠图。全部重画成 SVG：

- 圆、紫点用最小二乘拟合成正圆
- h 用矩形 + 圆弧拼
- 字标先试开源字体，对不上就用 potrace 描轮廓再把直边拉直
- 与原图的 IoU = 0.9886
- 分别放在白、灰、黑、篝火画面上 400% 放大检查，没有黑边、白边、锯齿

见 `scripts/tools/logo_build.py`、`scripts/assets/logo/`。

### 第 3 步　镜头背景：变速 + 推拉 + 质感

`scripts/prep_v8.py`：

1. 原素材插帧到 120fps
2. 按速度曲线积分，得到每一帧对应的源时间
3. 相邻插帧线性混合取样
4. 套推拉矩阵
5. 加速段叠 3 子帧运动模糊

其他镜头的曲线写在 `scripts/timeline.json`。

### 第 4 步　玻璃渲染：用开源 WebGL 内核

玻璃光学来自 [zanwei/glass-icon-reveal](https://github.com/zanwei/glass-icon-reveal)（MIT，作者 Zanwei Guo）。弹簧动画 `frameAt()` 和着色器都保留原版公式，我们只加了一项：让玻璃折射视频背景（`uBgTex`）。原版的玻璃后面只有纯色。

- 光学用原版 light look 数值：`dispersion 1.7`、`glow 1.25`、`edgeSmear 2.85`、`cornerPull 2.1`、`bevelWidth 0.14`、`opticalDepth 1.1`
- **h 要伸进斜面带。**h 占方砖约 75%，竖笔画两端和紫点伸进三个角，斜面里才有白色笔画可以折射出彩虹。否则黑场玻璃看起来没有折射
- 用 Playwright 无头 Chromium 逐帧渲染，每帧顺手导出方砖尺寸（glassinfo），给下一步画冲击波用

见 `scripts/glass/`。

### 第 5 步　后处理：冲击波和字标

- `scripts/tools/echo_wave_v12.py`：按 glassinfo 算出方砖边界，在左右两侧画波包
- `scripts/tools/wordmark_lens.py`：用 numpy + cv2.remap 做字标透镜的漩涡、拉开和 RGB 分通道色散
- `scripts/tools/build_v12_range.py`：每 30 帧开一个进程处理（本机内存紧，一次处理整片会 MemoryError）

### 第 6 步　声音：自己合成，不用参考片音乐

`scripts/music.py` 用代码合成 80 BPM 的声音：

- 每个切点一个底鼓
- 每次水滴落下一声玻璃铃
- 篝火冲击帧和加速点各一个轻鼓，加速段加一声"呼"
- 头发猛推处加上升音效
- 车经过一声呼啸，声像随车从右往左

### 第 7 步　合成编码

ffmpeg 一定要带 `-sws_flags lanczos+accurate_rnd+full_chroma_int`，并打 bt709 标签。不加的话白底会发黄。

每次出三个版本：

| 版本 | 编码 |
|---|---|
| 正式版 | CRF 16 |
| 微信版 | CRF 22，< 10MB |
| 对比版 | 上半我们、下半参考，只给自己对节奏，不外发 |

### 第 8 步　验收：逐段和参考并排看

每一段都和参考同一时刻并排比：动作、时间、比例、折射强度。只有内容替换和点名改动的地方可以不同。

逐像素检查：

- 开头 0.6 秒后，字标外的背景和 #e9e9e9 差 ≤ 1
- 结尾 10.2 秒后字标外是纯黑
- 全片 360 帧没有重复帧

## 12 版迭代复盘

| 版本 | 我的意见 | 改了什么 | 教训 |
|---|---|---|---|
| v1 | 图标漂移、折射不够、没波纹、篝火卡顿、结尾太快 | 固定正中、改用原版光学、结尾放慢到 12 秒 | 执行者会自己"优化"光学，方案里要写死不准改 |
| v2 | 字标左右摇、0.6 秒看不清就切走了 | 字标改成透镜展开、不旋转 | Codex 加了摇摆动画；执行改交 Sonnet |
| v3 | 玻璃没彩虹 | 恢复原版光学数值 | 执行者为了"干净"偷偷降光学强度 |
| v4–v5 | 滑板 logo 不要跟人动 | 改回固定正中 | 一个反例胜过十句描述 |
| v6 | 篝火被放大糊了、车不要擦黑 | 用原片完整画面，光流选入点，车经过后硬切 | 素材不准先放大再裁 |
| v7 | logo 震动那一刻画面要慢动作 | 四镜统一"慢—快"变速 + 插帧 | 变速规律要用光流量出来 |
| v8 | 开头有灰、篝火要推拉、两侧要水波 | 去灰、推拉 + 0.30× / 2.0×、两侧回声边 | 背景要逐像素纯净 |
| v9–v10 | 太差了，不如 v8 | 竖条翅膀被否 | 没看清就改，越改越偏 |
| v11 | 进步很多，但没散开、太多太密 | 加厚回声边，有质感 | "厚重"是线粗、辉光、玻璃体 |
| **v12** | **总算做出来了** | 一次一道波，往外走、由深到浅 | 去重平铺才看清运动 |

每一版的完整修改单在 [plans/](plans/)，每个参数决定和理由在 [plans/DECISIONS.md](plans/DECISIONS.md)。

## 踩过的坑，已经写成规矩

- **光学数值写死，不准降。**执行者为了"干净"会把色散砍半，改完一定和原版逐像素比颜色浓度。
- **logo 固定画面正中。**不漂移、不摇摆、不跟拍。
- **素材不放大裁切，不改色。**推拉用完整画面做，质感只做到"刚好"。
- **慢动作必须插帧。**否则一卡一卡。
- **看不清就换方法看**（高通、去重平铺、光流），再改参数。
- **只改点名的地方。**用户认可的版本锁住，其他帧直接拷贝。
- **本机内存紧。**渲染单进程，每 30 帧分段跑。
