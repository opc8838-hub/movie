05 技术规范

都是实际踩过的坑。主要给 AI 看。

编码

Python 或 canvas 管道出片，编码时一定带上这些参数，否则白底会发黄发绿：

-vf scale=out_color_matrix=bt709:out_range=tv:flags=accurate_rnd+full_chroma_int
-colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv
-pix_fmt yuv420p

验证： 抽一帧白场，按 bt709 转回 RGB，应该接近 255/255/255。

每次出这些版本：

版本 编码 用途
正式版 CRF 16 存档、发布
微信版 CRF 22，小于 10MB 发给人看
对比版 上半成片、下半参考 只给自己对节奏，不外发

素材入库

  • iPhone 视频默认 HDR（HLG、杜比视界）。 不转换会整片发白。入库先转 SDR：zscale + tonemap=hable，人物亮度一般用 npl=203
  • Live 图： .livp 是压缩包，里面有 HEIC 和 MOV，解开再用。常有重复帧、叠化重影帧，要逐帧看。可用的往往只有其中 1 秒
  • 手机录屏当参考： 先量出真实画面区域，比如 crop=592:334:0:335，并按可变帧率处理
  • 水印： 海螺、优酷都会有，交付前逐帧查
  • 方向： 前置摄像头是镜像，沟通时用“用户的左边”，先做举手测试
  • HEVC、旋转、可变帧率： 交给 ffmpeg 解码，不要交给网页

量参考片

想知道 方法
切点 select='gt(scene,0.25)' + showinfo，按 PTS 核对
帧时间 抽帧必须 -vsync passthrough，否则补重复帧会让时间错位（我们曾把苹果节奏量慢 1.45 倍）
肉眼看不见的淡波纹、灰边 灰度减高斯模糊 × 8–14（高通增强）
一段运动怎么走 mpdecimate 去重帧后平铺成一张图
镜头里哪里变速 光流算运动量曲线
歌词出现时间 按字的颜色逐帧数像素，数量一跳就是出新词，误差约 0.05 秒
选素材入点 滑动窗口算光流，挑动作起点落在目标节点的那一段

量参考要自己裁对区域、逐帧核对。 执行者曾把转角估得过快。

音乐踩点

  • 工具：Demucs 分离人声，faster-whisper 对词时间，librosa 找节拍和能量
  • 工具给的数只是草稿。 librosa 把一首歌测成 172 BPM，大约快了一倍，需要人听
  • 先测原曲。不要在剪过的文件上测拍点【借鉴】
  • 给每段标好：前奏、drop、乐句（长音 / 碎拍 / 呼吸）、高潮
  • 时间全部从节拍网格算，画面和音乐自然对齐

配乐来源：

来源 说明
代码合成 适合踩点音效、节奏明确的简单配乐。AI 听不到，好坏靠人的耳朵
Suno 写段落标签（[Intro: …]）能控制结构；风格里不能写音乐人名字；带 idempotency_key 防重复扣费
参考片音乐 仅限个人和内部，商用要换
海螺音乐 API 对新用户关闭

AI 镜头去假感

实测一次海螺 1080p 生成帧对比实拍 Live：

指标 生成 实拍
拉普拉斯方差（锐度） 249 9.4
1% 亮度（黑位） 0 15
99% 亮度（高光） 190 157

所以生成画面过锐、死黑，像 CG。入片前先量，再补：

处理 hely 玻璃片的定稿值
轻微柔化 gblur 0.4
抬黑位 7/255（6–10）
高光柔压 ≤ 248
细颗粒 σ≈2.2/255
亮部光晕 4%（3–5%）
暗角 无
色相 不动

宁轻勿重。 主理人说过：“不是做旧，是质感，不要太刻意，刚好那种。”验收时列出处理前、处理后、实拍三组数，放大 200% 对比。

变速与慢动作

规律（来自 hely 玻璃片的光流实测）：

正常速度 → 冲击帧骤然放慢 → 关键内容都在慢动作里 → 退场后加速 → 冲进硬切

minterpolate=fps=120:mi_mode=mci:mc_mode=aobmc:me_mode=bidir:vsbmc=1

插完放大 200% 看边缘。脸和手的处理见第 02 章。

详细方法见 hely 玻璃片的动态语法六条。

抠像和合成

  • 绿幕：色差抠像 + 去溢色
  • 任意背景真人：净背景差值保发丝 + isnet 保身体；不要用 AI 人像范围直接压 alpha（isnet 不认椅子）；只留连通大块
  • 产品：白床垫贴白墙时 isnet 会破洞
  • 逐帧视频抠图：约 3 秒/帧，一次只跑一个 AI 进程
  • 真实画面尽量不拆层。歌词藏人身后这类可以，但要放大查毛边
  • 手写字：Zhang-Suen 细化后沿中心线路程显现

机器和环境

主要制作机内存紧、显卡弱（GeForce GT 610，16GB 内存）：

  • 不跑本地 AI 大模型；对口型走云端
  • 渲染一边算一边写 ffmpeg 管道，不把整段放内存
  • 重渲前查空闲内存，大于 3500MB 再开；AI 抠像同时只跑一个
  • 长片分段，每 30 帧一个进程，避免 MemoryError
  • 主理人常开着剪映和桌面 AI 客户端，内存不够时提醒关闭
  • 浏览器逐帧渲染，每 50 帧重启一次防内存爆
  • 网页动效上线前在真实机器开窗测帧率；WebGL 导出要加 --use-angle=swiftshader

Windows 上：

  • cv2.imread 读不了中文路径，用 cv2.imdecode(np.fromfile(...)) 或 PIL
  • Python 脚本用 python -X utf8

工具的坑

工具 坑
海螺 API 国内接口直连，走代理会握手超时、静默卡死。Hailuo-02 首尾帧最短 6 秒；H3 系列走 v2 接口
海螺配音 克隆音色 7 天不用会删。数字写汉字，型号写念法（“L Y 六百”）
Codex 新版路径常变，用真有 codex.exe 的目录；Windows 沙箱常失败，图常留在 ~/.codex/generated_images/；15 分钟没产出就重来；额度有限，不要一次画太多
子代理 同时开 4 个会撞额度。禁用素材要写完整路径，验收专门查。要求如实报告，否则会报“完美”
执行者 会偷偷降低参数，或自己“优化”。方案里写死，并和原版逐像素比
Git 推送失败先查代理端口，不要盲目重试

配音（品牌片）

  • 开工就发录音要求，不合格宁可重录
  • 逐句生成，单句可重配
  • 讲话镜头放慢到约 0.85 倍更有苹果味
  • 整体约 -16 LUFS

隐私和发布

  • 密钥放 .env，不进仓库
  • 公开仓库不放：原始素材、音乐、参考片、客户内部文件
  • 发布前查 Git 实际跟踪的文件，不要只相信 .gitignore
  • 只放我们自己的成片截图
  • 苹果产品图等第三方素材只限内部和测试，对外要换可商用素材
  • 示意性的证书、假专利对外前必须换成真的
