# 03 镜头怎么选

开工前先判断：这个镜头用实拍、代码还是 AI？选错了比提示词写错更费钱。

---

## 总表

| 镜头 | 用什么 | 不要用 | 依据 |
|---|---|---|---|
| 真人讲话、露脸 | 真实视频，必要时逐帧换背景 | 图生视频（会变形、改构图）；逐帧 AI 改图（闪烁） | 连盈 |
| 只有照片的真人，走路、转身 | 一张定场 + 人物参考 + 参考动作视频；或倒放法 | 多张关键帧硬锁 | MV1、MV2、MV3 |
| 真实产品 | 真实照片和视频，配代码动效 | 让 AI 画产品（结构会错） | 连盈 |
| 产品零件合拢 | 分层爆炸图 + 代码合拢 + 2.5D 绕拍 | 单张图算 3D 转身 | 连盈 |
| 手机、卡片这类规整物体 | three.js 真 3D，或代码引擎 | 视频模型多段拼接（动作不连贯） | 三星堆 B2W v3、无重力翻转 |
| 头像转身这类有机动作 | 代码和模型各试一小段，都不行就补真实素材 | 认定某一种方法一定行 | 三星堆升级 v8–v10 |
| 零件悬浮靠拢 | 首尾帧能给够信息时用模型 | 只给首帧（会乱变形） | 三星堆升级 v8 |
| 云、光、城市夜景 | AI，入片前去假感 | 直接入片 | jd、hely 漫步 |
| 衣服转身 | 视频模型生成旋转，抽帧成序列 | CSS 旋转（像纸片） | 衣架站 |
| 插画微动循环 | 首尾帧锁同一张图 | 不锁尾帧（必跑偏） | 插画立体世界 |
| 小动作：眨眼、发丝、落泪 | 九宫格切帧或 GIF | 指望它做大动作（越多帧越糊） | gif-anime |
| 文字、数据、图表 | 代码 | AI（字会错） | 碳基、专利翻阅 |
| 风格化场景、艺术风格 | 代码画，可以逐帧控制 | 全部交给 AI | 东莞国贸、huashu-art-motion |

**没有绝对的答案。** 三星堆 B2W 的手机段，代码赢了模型。三星堆升级的转身段，代码被嫌不够自然，换成模型又“不如以前”，最后用主理人补的素材才解决。所以有争议的镜头先各试一小段，别讨论太久。

## 视频模型怎么用

### 首尾帧能不能锁

判断标准：**两张图是不是同一机位、同一衣服、几何一致？**

| 情况 | 做法 | 依据 |
|---|---|---|
| 同机位、同衣服、动作小 | 首尾帧锁死 | MV2 判断 |
| 有衣服或物件不一样 | 先改图再锁，否则衣服会“融化”成另一件 | MV2 第一次失败 |
| 景别或身体朝向不一致 | 不要首尾帧，用倒放法 | MV3 |
| 多张关键帧比例不一致 | 只留一张定构图，其他只做长相参考 | MV1 方案二 |
| 两张图动作只差一步 | 不用 Hailuo-02 分段：它最短 6 秒，模型会原地东张西望再硬变；改用可设短时长的工具，或一条连贯生成 | MV1 |

检查比例不一致的小办法：在图里找一个固定参照物。MV1 用台阶上的小孩当尺子，发现头和小孩的比例从 0.64 跳到 1.09，变形原因一下就清楚了。

### 倒放法

**我们自己总结的做法，解决“结尾必须是真人照片”的问题。**

1. 首帧锁住正脸真照片
2. 参考视频用原片动作的倒放版
3. 生成“正脸 → 转走”
4. 后期倒放

这样片子的结尾就是真照片，脸不用让 AI 画出来。MV2 和 MV3 都用了这个做法，比首尾帧干净很多。

注意：后段完整侧脸可能不像本人，只取前面好的部分。

### 哪个模型做什么

| 需求 | 建议 | 依据 |
|---|---|---|
| 真实感、衣服转身 | MiniMax H3-Max | 衣架站，9 条一次成功 |
| 插画循环、怕重画脸 | MiniMax H3 2K + 锁尾帧 | H3-Max 会重画脸 |
| 高清人物、参考动作 | 即梦（网页，主理人操作） | MV1、MV3 |
| Seedance 2.5 / 2.0 mini | 【待验证】我们还没走 API | Eian 的价格和毛病表，见下 |

### 提示词易错表

以下是我们和 Eian 都遇到过的模型习惯。

| 问题 | 写法 |
|---|---|
| 人物嘴自己动 | 写明人物不说话、嘴闭合；还动就用代码修或作废 |
| 一群人同时做一样的动作 | 写清谁先谁后；首帧不要摆同一姿势【借鉴】 |
| 人往反方向走 | 按画面写：“朝画面左边走”【借鉴】 |
| 东西凭空出现 | 只用首帧已有的东西【借鉴】 |
| 雨、帽子、纹身拍着拍着没了 | 首尾帧都画上【借鉴】 |
| 写“不要什么”没用 | 改成正面说法：“画面里一直只有这几个人”【借鉴】 |
| 动作太多就乱 | 每个镜头只写一两个主要动作【借鉴】 |
| 墨镜这类小配饰变形 | 单独给一张特写，并详细描述形状（MV1） |

更完整的列表见 [Eian 原文](https://x.com/EianLu/status/2118317430665613741)。

### 生成后处理

- 去水印：能裁就裁；不能裁时用真照片补水印区（MV2）
- 黑边：先裁掉再放大，高度取偶数
- 帧率：60fps 两帧平均成 30fps
- 质感：见[第 05 章](05-tech.md#ai-镜头去假感)

## 省钱规矩

- **花钱前报价，等人同意。** 不擅自调用付费视频
- 能做一个小样就不要跑全部，先跑最难的镜头
- 先用低分辨率，定稿再出高清【借鉴】
- 接口报欠费就停，先把已有片段粗剪给人看，不自己充值

## 代码动效怎么做

**流程：** 量参考 → 一个能双击打开的网页 → 参数集中到文件顶部 → 静帧检查 → 导出 MP4 → 存档参数。

好的习惯：

- **时间函数化：** 任意时刻都能渲出同一帧（`window.__render(t)`），才能逐帧导出，结果也可复现
- **世界坐标：** 用参考片实测的像素当坐标，缩放关系天然对
- **曲线用 bezier 拟合：** 实测点有误差，逐点穿过会抖
- **衔接帧逐像素一致：** 下一段的开头直接从上一段导出，我们连播三段时接缝的逐帧差小于 0.5

常见的坑：

- `bezier` 在 0 处返回极小正数，第一帧就动了；两端要强制为 0 和 1
- 大量粒子后用 `ctx.filter` 模糊，每帧从 5ms 涨到 300ms；改用叠淡影
- 离屏模糊画布太大会卡；按镜头大小降分辨率
- 用户双击 `file://` 打开时，WebGL 读不了本地图片；把图片打包成 data URI。测试时别开放行开关，否则发现不了
- 无头 Chromium 不放 H.264，截图用 Edge
- 性能要在真实机器上开窗测，低端显卡上 MSAA 可能把 60 帧打到 36 帧
